Ответы на вопросы
1. Чем int.TryParse() безопаснее int.Parse()? В каких случаях стоит использовать каждый?
int.Parse() вызывает исключение (программа аварийно завершается), если строку невозможно преобразовать в число. int.TryParse() в этом случае просто возвращает false, и программа продолжает работу. int.Parse() можно использовать, если вы на 100% уверены в данных (например, они пришли из вашей же базы данных). int.TryParse() нужно использовать при вводе данных от пользователя, чтобы программа не сломалась из-за случайной опечатки.

2. Когда switch удобнее, чем цепочка if/else if? Приведите пример из реальной жизни.
switch удобнее, когда мы сравниваем одну и ту же переменную с набором конкретных значений (констант). Это делает код визуально чище и понятнее. Пример из реальной жизни: обработка нажатия клавиш на клавиатуре в игре (нажата клавиша "W" — идти вперёд, "S" — назад, "A" — влево и т.д.) или меню в банкомате (1 — снять наличные, 2 — пополнить счёт, 3 — оплатить услуги).

3. Что произойдёт в switch, если убрать break после одного из case?
В C# это вызовет ошибку компиляции, если в блоке case есть исполняемый код. В отличие от языков C или C++, в C# запрещено «проваливание» (fall-through) в следующий case (если только блок не пустой, что используется для группировки). Это сделано для защиты от случайных логических ошибок.

4. Чем отличается = от == в C#? Почему это частая ошибка?
Один знак = — это оператор присваивания (записывает значение в переменную). Два знака == — это оператор сравнения (проверяет на равенство). Это частая ошибка, потому что в математике мы привыкли использовать = для обозначения равенства, и при написании кода палец может машинально нажать один знак вместо двух.

5. Можно ли написать тернарный оператор внутри другого тернарного оператора? Приведите пример из кода лабораторной и оцените читаемость такого кода.
Да, можно. В лабораторной работе был пример определения температуры:

csharp
string weather = temp >= 20 ? "тепло" : (temp >= 0 ? "прохладно" : "мороз");
Читаемость такого кода снижается, если вложенность становится больше двух. В приведённом примере код ещё читаем, но если добавить третье или четвёртое условие, то лучше использовать конструкцию if/else if/else или switch. Тернарный оператор лучше оставлять простым и коротким.
